3. 기능과 시험

기획서의 기능 7가지와 시험 166개입니다.

기능내용
파일 읽기CSV·TXT·엑셀 여러 개. 구분자와 머리말(시작 시각·샘플링 주기)을 스스로 찾고, 파일 카드에서 시간 열·단위·시작 시각을 고칩니다.
시간 동기화시작 시각 차이로 옮긴 뒤 교차상관으로 지연을 추정합니다. r 이 낮거나 최대 지연 끝이면 경고하고, 직접 입력도 됩니다.
전처리채널마다 배율·오프셋·영점·이동평균·저역통과·이상치 기준과 처리 방식을 정합니다.
결과 그래프·통계정규화 겹쳐 보기, 보기 구간, 채널 켜고 끄기, 이상치 표시. 보간값 채널을 구분합니다.
내보내기·요약동기화데이터·처리이력·채널통계·이상치·요약 엑셀, CSV, 요약 문장(선택: AI 다듬기).
3D 그래프예제·동기화 결과·표 파일에서 X·Y·Z 를 골라 Canvas 에 직접 투영합니다. 끌어 돌리고 휠로 확대, PNG 저장.

6. 한계와 남은 일

  • 구조물 수명평가·용접부 피로평가(IIW·BS7608)는 계산 기준 검증이 필요해 이번 판 범위 밖입니다.
  • 용접부 각장 설계 프로그램은 하지 않습니다.
  • 계측기 전용 바이너리 형식은 직접 읽지 않습니다(CSV·엑셀로 내보내 올림).
  • 일정한 지연 하나만 보정합니다. 시계 드리프트는 보정하지 않습니다.
  • 물리량이 다른 신호의 지연 추정은 응답 모양만큼 치우칠 수 있어 보정 전후 그래프로 확인해야 합니다.
  • (v1.1) 3차 이상 · 비선형 회귀는 하지 않는다(계수 6개 2차까지). 라벨(Safe)의 뜻을 정하지 않는다. 기획자 html(Plotly)은 참고만 했고 라이브러리를 들이지 않았다.
  • 업무 자료는 지금처럼 브라우저 안에서만 처리합니다. 로그인 DB 에는 「누가 쓸 수 있는가」와 게시판 글만 있습니다.
  • 로그인 뒤 화면(게시판 · 관리 · 첫 화면 고르기)은 실제 계정으로 눌러 보지 않았습니다. 가입 → 사용 신청 → 승인 → 게시판 글쓰기 확인은 기획자와 관리자 몫입니다.
  • 독립 운영까지 남은 것: 본인 Supabase 프로젝트에 auth.sql · board.sql · site.sql 실행 → js/auth-config.js 의 url · anonKey 교체 → 다시 배포(supabase/README.md)
